BewerbungsKI – Übergabe-Dokument

Stand: 13. August 2026. Dieses Dokument macht einen anderen Assistenten mit der App vertraut, damit er sie bearbeiten kann.

1. Was ist die App?

  • bewerbungski.com — KI erstellt Lebenslauf + Anschreiben für den deutschen Arbeitsmarkt (DIN 5008, ATS-optimiert).
  • 9-Schritte-Assistent: Persönliche Daten → Schulabschluss → Ausbildung → Berufserfahrung → Skills → Sprachen → Stellenanzeige → Vorlage (14 Templates) → Generieren.
  • Extras: Freitext-Schnelleingabe („Schnell eintippen“, KI sortiert formlosen Text in die Felder inkl. Stellenanzeige), LinkedIn-Import, Foto-Upload, DOCX-Export, gespeichertes Profil, Live-CV-Editor, Dark Mode.
  • UI in 8 Sprachen (de, en, es, pl, ru, tr, uk, ar inkl. RTL); Bewerbungssprache wählbar.
  • Mobile-App (Expo/React Native) existiert zusätzlich.

2. Preismodell (seit 13.08.2026)

  • 3 Bewerbungen kostenlos pro Konto, danach 9,99 € einmalig für 30 weitere (kein Abo, nichts „unbegrenzt“).
  • Serverseitig erzwungen: ohne Kauf ab 3 Dokumenten gesperrt (free_limit_reached), mit Kauf ab 33 Dokumenten gesamt (premium_limit_reached; 33 = 3 gratis + 30 gekauft).
  • Stripe-Webhook checkout.session.completed setzt profiles.is_premium = true. Preis ist inline (unit_amount: 999), keine Stripe-Price-ID.
  • Bei Preisänderungen synchron halten: checkout.ts, generate.ts, alle 8 Sprachdateien, index.html (Meta + JSON-LD), Mobile-App.

5. Deployment (nur so funktioniert es!)

  1. Bei Frontend-Änderungen: pnpm --filter @workspace/bewerbungski run build
  2. tar.gz des Workspace erstellen (ohne .git, node_modules, .local, .agents, attached_assets, .cache, .pythonlibs, Mobile, Sandbox)
  3. POST als application/gzip an backboard.railway.com/project/f88e5c3f-e1b6-4616-8ecc-e1fa02832d0c/environment/19490e15-3d0c-48f0-a0eb-477175ddf001/up?serviceId=f987ee0c-b556-4749-997e-80402be24654 mit Header Authorization: Bearer $RAILWAY_TOKEN
  4. Status per GraphQL deployment(id){status} pollen (~60–90 s)

⚠️ Die Railway-CLI und Multipart-Upload funktionieren mit diesem Token NICHT. Beim Start läuft drizzle push --force automatisch (railway.json).

7. Regeln des Besitzers (unbedingt beachten)

  • Besitzer: Raphael Halim — nicht-technisch, deutschsprachig, nur am Handy, sehr kostenbewusst: wenige Deploys, einfache deutsche Erklärungen, kein Fachjargon.

8. Bekannte Stolperfallen & offene Punkte

  • Supabase Free-Tier pausiert automatisch, wenn sich der Besitzer nicht wöchentlich einloggt → Login + Bezahlung fallen aus.
  • KI-Fehler bedeuten meist: Anthropic-Guthaben leer.
  • /api/download/RaphaelKI2026 ist ein öffentlicher, unauthentifizierter Info-Download — Absicherung ist eine offene Aufgabe.
  • Premium-Nutzer, die alle 30 Bewerbungen verbraucht haben, können noch kein weiteres Paket kaufen (offene Aufgabe).
  • Mobile-App zeigt teils noch alte Preise/Texte (offene Aufgabe).
  • documents_count wird live gezählt (COUNT auf documents) — Löschen von Dokumenten gibt Kontingent frei.
  • Nach Schema-Änderungen pnpm --filter @workspace/db run push; nach OpenAPI-Änderungen Codegen laufen lassen.
